> 主人明确的终极目标：**独立 exe 软件，别人下载后双击就能用**。
> 不依赖 Python 环境、不依赖任何 AI 工具/服务、不依赖开发者机器上的任何东西。
> 本文档是验收标准：今后每个功能都要回答「用户拿到 exe 后这个功能还能用吗」。

## 一、现状 vs 目标的差距（按严重程度排序）

### 🔴 1. 数据写死在程序目录，装进正规目录就没法用

现在 `BASE = Path(__file__).parent`，config.json / pet.pid / logs/ / assets/user/ 全写在 exe 旁边。
用户把 exe 放进 `C:\Program Files\` 或 `C:\Program Files (x86)\`（正规安装位置）后，
**普通权限进程没有写权限**——保存位置、生成桌宠、写日志全部静默失败（现在 except pass 都吞了，表现为「设置不生效」还查不出原因）。

**改造**：拆成两个目录——
- 程序目录（只读）：exe + 自带素材（oc/ whale-girl/ 内置形象、boop.wav 生成逻辑保留）
- 数据目录（可写）：`%APPDATA%\DeskPet\`（config.json、pet.pid、logs/、assets/user/、assets/bubbles/）
- 读取顺序：数据目录优先，没有就回落程序目录（保持开发期行为不变）
- 这个改造要在打包之前做完，它是所有「别人机器上莫名失效」问题的根源。

### 🔴 2. rembg 模型不在包里，离线用户 AI 抠图直接废

`rembg.new_session("isnet-anime")` 默认到 `~/.u2net/` 找模型，**找不到就从 GitHub 下载（约 170MB）**。
用户网络不通 / GitHub 被墙 → AI 抠图第一次点击就异常。这不符合「下载即可用」。

**方案三选一**（建议 A）：
- A. **完整版随包带模型**：打包时把 onnx 模型放 exe 旁 `models/` 里，`new_session` 前设置
  `os.environ["U2NET_HOME"] = str(BASE / "models")` 指过去。体积 +170MB，换「开箱即用」。
- B. 精简版（纯算法抠图）+ 完整版（带模型）两个下载档，安装时选。
- C. 首次使用 AI 抠图时弹窗引导下载（带进度条和失败提示），绝不能静默失败。
- 无论哪种：`ai_status()` 返回不可用时 UI 文案要写成「组件未下载」而不是「缺库」——用户不懂什么是 onnxruntime。

### 🟡 3. 打包方式

- **PyInstaller onedir 模式**（一个文件夹 + 主 exe）：启动快（<1s）、杀软误报相对低。onefile 虽然好看，但每次启动解压到临时目录要 3~5 秒，桌宠这种常驻程序不值得。
- 必带：`--windowed`（无黑框）、图标、PySide6 的插件目录（PyInstaller 一般能自动收，托盘图标要 Qt 的 `qsvg` 插件，打完包必须真机验证托盘能显示）。
- numpy/scipy 体积大但躲不掉（抠图引擎靠它），预计 onedir 全包 300~400MB（带模型）。可接受；想瘦身可以用 `--exclude-module` 砍掉 scipy 里用不上的子模块。
- **杀软误报**：无签名的 PyInstaller exe 被 Windows Defender / 国内管家误报是常态。短期：README 里写「如被拦截请添加信任」；长期（可选）：买代码签名证书。这一条不影响开发，影响发布口碑，先知道。
- 开机自启的 `.lnk` 指向路径会自动变成 exe 路径，`set_autostart` 逻辑不用大改，但要验证。
- 「打开文件夹」「上传图片」的 QFileDialog 在打包后行为不变，低风险。

### 🟡 4. 双进程结构在 exe 下的细节

`start_pet` 用 `sys.executable` 推导 pythonw 的逻辑要改成：打包后直接 `sys.executable + ["--pet"]`
（同一个 exe 用参数区分「控制台模式 / 桌宠模式」两个入口，最干净），或者带两个 exe。
推荐单 exe 双模式：`petctl.pyw` 无参数 = 控制台，`--pet` = 桌宠本体。pid 文件、TerminateProcess 逻辑不变。

### 🟢 5. 卸载与重置

绿色版卸载 = 删程序目录 + 删 `%APPDATA%\DeskPet` + 删自启 lnk。控制台里加一个「恢复初始设置」按钮
（清配置文件重启）就能覆盖 90% 的售后场景。不急，发布前有就行。

## 二、对现有功能的影响评估

| 功能 | exe 下可用性 | 备注 |
|---|---|---|
| 壁纸层/置顶、拖拽、点击、气泡 | ✅ 不受影响 | 纯本地 Qt/WinAPI |
| 算法抠图 + 动画生成 | ✅ 不受影响 | numpy/scipy 随包 |
| AI 抠图 | ⚠️ 需按第 2 条处理 | 模型必须随包或引导下载 |
| 音效/图标 | ✅ | winsound 随 Python 打包 |
| 配置/自启/托盘 | ⚠️ 路径迁移后需回归测试 | 第 1、4 条 |

**结论：这个项目不需要任何联网 AI 服务，天生就是离线软件，方向完全正确。
要做的是「数据目录拆分 + 模型随包 + 打包验证」三件事，都是工程活，不伤现有架构。**
