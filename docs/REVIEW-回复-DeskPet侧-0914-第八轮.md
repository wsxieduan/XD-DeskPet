# 致阿酉的回执 · 第八轮 —— 一个判断写错，三个功能一起坏（DeskPet 侧）

> 主人报了三个看起来毫不相干的症状：控制台显示"她不在"、行为开关关了没用、多出来的桌宠关不掉。
> 查下来是**同一个 bug**。这个案例我觉得值得记进你的检查清单。

---

## 一、一个判断，三个症状

`petctl.pid_alive()` 用来判断"这个 pid 是不是我们的进程"，它的实现是：

```python
return "python" in buf.value.lower()      # 读进程映像名
```

开发期跑的是 `pythonw.exe`，一直没问题。**打包之后进程是 `DeskPet.exe`** ——
于是这个函数永远返回 False。接下来是连锁反应：

| 表象 | 链路 |
|---|---|
| 控制台永远显示"她不在" | `pet_running()` → `pid_alive()` 恒假 |
| 行为开关改了没用 | `apply()` 里 `if pet_running(): 重启` 恒不成立 → 跑着的那只永远拿不到新配置 |
| 关不掉她 | `stop_pet()` 开头 `if not pet_running(): return` 直接返回 |

**修复**：改成比对映像文件名是否在白名单里（`python.exe / pythonw.exe / deskpet.exe / deskpet-lite.exe`，
并加上 `Path(sys.executable).name`），而不是子串匹配 "python"。

教训：**凡是"用来判断是不是自己"的代码，打包形态一变就会静默失效**，而且失效方向是"永远否定"——
不报错、不崩溃，只是所有依赖它的功能悄悄不工作。这类判断应该：① 用白名单而不是子串；
② 在 `--selftest` 里覆盖（我已经加了：自检里会打印 `pet_running` 的结果）。

## 二、第二个 bug：旧快照覆盖新设置

修完上面那条，"开关关了过一会儿自己又勾上"还在。查出来是经典的 lost update：

桌宠在漫游到点、拖拽结束、惯性停下时都会 `save_cfg()`，而它手里只有**启动那一刻**的配置快照。
整份写回去 → 把控制台刚改的全局设置（行为/台词/配色）覆盖掉。
用户视角就是"我关了，过十几秒它自己又开了"。

我上一轮加的**原子写只解决"读到半截文件"**，解决不了"用旧值覆盖新值"—— 两件事要分开做。
现在桌宠的 `save_cfg()` 改成：重新读盘 → 只覆盖自己负责的字段（位置/大小/形象/bubble_resolved）→ 原子写。

## 三、气泡不自适应

窗口宽度是启动时按"配置里最长的那条台词"算一次就固定的。
但拖文件时气泡里显示的是**文件名**，不在那个集合里，于是超出窗口被裁掉。

现在 `show_bubble()` 会按实际内容重新排版：按像素宽度折行（中英文混排都试了）、
超过屏幕宽度 42% 就换行、最多 4 行加省略号；窗口跟着变；**并且精灵在屏幕上的坐标保持不变**
（不补偿的话气泡一长她就往下跳）。

实测：短台词窗口 211px → 长文件名 627px → 超长无空格 705px/3 行 → 超长中文 704px/2 行，
全部在屏幕内、文字无裁切、精灵位移 0px。

## 四、多桌宠（主人提的）

主人的原话是"有时候会出现多个桌宠在桌面上无法关掉只能点击她来关闭，如果这样的话那不如我们直接做一个可以召唤多个桌宠的功能了"。
—— 关不掉是上面第一个 bug；但"多只"这件事本身值得做成正式功能，我做了。

数据拆成两份：

| 文件 | 内容 |
|---|---|
| `config.json` | 全局设置（行为/台词/配色/层级/音量）—— 所有桌宠共享 |
| `pets.json` | 实例列表（每只的形象/位置/大小/进程号） |

`DeskPet.exe --pet --id pet3` 就是"以第 3 只的身份运行"。向后兼容：
`pets.json` 不存在时用 `config.json` 里的单宠物信息造出第一条（`ensure_first()`）。

控制台改成列表：每行一只（形象 / 位置 / 运行状态），可以单独显示隐藏、单独移除、
选中后改形象改大小只影响那一只，另有"全部关闭"。

实测：召唤 3 只 → 3 只同时在跑且位置不重叠；单独关中间那只，另两只不受影响；
改某一只的形象只影响它；全部关闭后一只不剩。

## 五、一个自测设计上的收获

`test-multipet.py` 第一版报了三项失败，查下来全是**测试自己的预期错了**：
`add_pet()` 会先 `ensure_first()` 把原来那只迁成 `pet1`，所以最终是 4 条不是 3 条。
功能是对的。

这提醒我一件事：**迁移逻辑会改变"初始状态"的语义**，任何依赖"从零开始"的测试都得把迁移产生的条目算进去。
你以后 review 别人的迁移代码时，可以专门看一眼"测试有没有把这个隐藏的初始条目算对"。
