# 轻量化路线分析 · 参考 Petra（阿酉 · 2026-09-14 20:40）

> 背景：主人找到 Petra（github.com/Wumiu/Petra，Tauri + TypeScript/Pixi + Rust），
> 认为「做到比我们好」，目标是**极致轻量化**。
> 本文档回答两件事：Petra 强在哪、我们怎么应对 + 轻量化到底怎么做。

---

## 一、先纠正一个概念：Petra 轻在「分发」，不轻在「运行」

轻量化有三条完全不同的线，别混：

| 线 | Petra | 我们（现状） |
|---|---|---|
| **分发体积**（下载多大） | 小：Tauri 不打包浏览器引擎，用系统自带的 WebView2，安装器几 MB～几十 MB | 大：PyInstaller 全包 300~400MB（numpy/scipy/PySide6 + 170MB 抠图模型） |
| **运行内存**（挂着占多少） | 中等：WebView2 进程链 + WebGL 页面，实际 80~200MB，并不省 | 相近：PySide6 + 帧纹理，~100MB 量级 |
| **依赖复杂度** | 需要用户系统有 WebView2（Win11 自带，Win10 大多自带） | 零依赖，解压即用 |

**结论：Petra 不是运行时的标杆，是分发体积的标杆。** 我们在「挂着跑」这件事上和它是一个量级。
差距在下载体积——而那 300MB 里，**约 250MB 是 AI 抠图链（onnxruntime + rembg + 模型）**，
这是砍掉它最充分的理由。

---

## 二、Petra 真正的优点（按价值排序，要诚实承认）

1. **表现力代差**：Anime2.5DRig 拖入分层 PSD 自动装配 2.5D 角色——视线追鼠标、发丝物理、
   眨眼、口型、软体晃动。这是「分层网格变形」，和我们的「单图仿射帧动画」是两个物种。
   这一条硬追不上，后面单说对策。
2. **行为系统**：漫游、躲避鼠标、逗猫棒、待机沉到屏幕边缘倒挂、活动频率三档、拖拽惯性。
   这些是**纯逻辑**，跟渲染技术无关——**这才是桌宠「活着」的灵魂，而且我们抄得动**（见第三节）。
3. **发布工程成熟**：安装器、自动更新、日志埋点（boot:start 序列）、%APPDATA% 数据目录、
   DPAPI 加密存 key、隐私说明/许可致谢/免责声明齐全。我们的《发布约束》方向和它完全一致，它跑在前面而已。
4. **AI 是可选增值**：不填 key 就是纯桌宠。印证了「核心离线、AI 加值」——和主人的 exe 约束同路。

## 三、不换技术栈就能直接偷的（高价值低成本，建议全做）

| 偷什么 | 成本 | 备注 |
|---|---|---|
| 行为系统：漫游 / 随机走动 | 低 | 现有 running 轨道 + 位置插值，QTimer 随机决策即可 |
| 待机沉到屏幕边缘（倒挂可不做，先做「蹲边」） | 低 | 位置动画 + rotate 180° 的帧都是现成仿射变换 |
| 躲避鼠标（光标靠近弹开） | 低 | 光标坐标已在读，加个距离判定 |
| 拖文件到桌宠 → 送回收站 | 低 | Python `send2trash`，drag&drop 事件 Qt 现成 |
| 拖拽惯性摆动 | 低 | 已有 sway 轨道，松手时按拖拽速度播一次即可 |
| 双击托盘/快捷键隐藏唤出 | 低 | 已有托盘，加个全局热键 |
| 日志埋点序列（boot:start → boot:loop） | 极低 | 排障习惯，抄 |
| 发布文档三件套（隐私/许可/免责） | 极低 | 发布前必做 |

## 四、表现力代差的对策（重要决策，先定方向）

**不建议追 2.5D 装配**。理由：Anime2.5DRig = WebGL 网格变形 + 物理引擎 + PSD 解析 + 自动骨骼，
Python 生态没有现成好轮子，自研是几个月量级；而且它依赖「单图拆层」（See-through）这种外部服务，
与主人「下载即用、离线」的目标冲突。

**务实路线：把「单图桌宠」的行为与交互打磨到极致**（上面第三节清单全做），
表现力用「多立绘 + 多轨道」补偿：支持上传**多张姿势图**（站/坐/睡各一张）映射到不同轨道——
README 已知边界里就写了「想要更丰富的动作需要多个姿势的立绘」，把它做成正式功能即可。
以后若真要 2.5D/Live2D，那是「换栈（Tauri 或 C#）时一起重估」的事，不是现在。

## 五、极致轻量化执行清单（给 dsh 的行动项）

1. **发布改双档**：
   - 精简版（推荐主推）：**移除 AI 抠图整条链**（rembg + onnxruntime + 模型，-250MB+），
     上传界面用现成的 suitability 引导 + 「推荐用任意抠图工具出透明底 PNG 再上传」文案（已有基础）。
     预期 onedir **60~90MB**，安装器压缩后 30MB 上下。
   - 完整版：保留 AI 抠图，给重度用户。
   - 控制台「关于」里注明两档区别。
2. **scipy 可选瘦身**：只用了 label/mean/std/fill_holes/dilation/sobel——
   若追求极致可换纯 numpy 实现（label 较麻烦），**性价比低，放最后，不阻塞打包**。
3. **运行内存**：非当前轨道的 QPixmap 可在切轨道时再加载（素材小，收益一般）；
   真正要省就压帧尺寸，先不动。
4. **打包验证照旧**：无 Python 真机 + Defender 误报检查。

## 六、总评

Petra 是个完成度很高的项目，值得敬意，但**它赢在 2.5D 表现力和发布成熟度，不是赢在轻量**。
我们的正确姿势：不跟它拼渲染（那是换栈级别军备竞赛），拼「轻、稳、行为可爱」——
一个 60MB、双击即用、会在桌面溜达躲鼠标的桌宠，本身就站住了。把第三节清单做完，
我们缺的不是技术，是把「她活着」的那部分补上。
