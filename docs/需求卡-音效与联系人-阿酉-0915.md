# 需求卡：自定义互动音效 + 桌宠联系人绑定（阿酉 · 2026-09-15 14:20 · 主人提出）

> 主人两个想法：① 用户可上传自己的音效并绑定到桌宠互动；② 桌宠之间建立「联系人」，
> 在桌面上一起动。两项都可行，难度一低一中，设计如下。

---

## 功能一：自定义互动音效（难度：低，半天）

### 设计
- **音效库目录** `assets/sounds/`（随包内置 3~5 个：boop/pop/铃铛/喵…，可程序生成）+
  用户上传的同目录管理；控制台加「音效」分组。
- **绑定粒度**：按互动类型绑定，而不是全局一个——`点击` / `拖拽抓起` / `落地` / `生成成功`
  四类起步。每类可绑**多个**音效，触发时随机播一个（和台词池同一个思路）。
- 存储：config.json 加 `"sounds": {"click": ["sounds/a.wav", ...], "land": [...]}`，
  空列表回落内置 boop（老用户无感升级）。
- 上传界面：文件选择器 + 试听按钮 + 「恢复默认」。

### 技术要点（有一个坑）
- 现在用 `winsound.PlaySound`，**只支持 WAV**。用户手上的多是 MP3/OGG：
  - v1 方案（推荐）：**只收 WAV + 控制台文案说明格式**，保持零依赖零体积；
  - v2 方案：换 QtMultimedia 的 QSoundEffect（支持 MP3），代价是打包多 ~10MB 的媒体模块——
    和轻量化目标冲突，除非用户强烈要求，否则先不做。
- winsound 的 PlaySound 本身是异步的（SND_ASYNC），连续触发会打断上一条——音效短（<1s）无感，文案里建议用户用短音效。

### 验收
- [ ] 上传一个 WAV 绑定到「点击」，摸桌宠听到新音效
- [ ] 绑定多个音效时随机播放；清空回落默认
- [ ] 精简版/完整版行为一致；上传非 WAV 时有明确提示

## 功能二：桌宠「联系人」绑定（难度：中，2~3 天）

### 前提确认
多只同屏的基础已经在了（test-multipet 通过、pets.json 已出现）。这张卡只做「绑定关系 + 联动行为」。

### 设计（最小可行，按价值排序）
1. **绑定关系**：控制台/右键菜单里给两只桌宠互设「联系人」，存进 pets.json
   （`"friends": ["pet-id-2"]`，双向）。
2. **跟随**：被绑定的一方在空闲时有概率跟随另一方漫游——保持 80~150px 的跟距，
   对方停下自己也停下（直接复用漫游插值，只是目标点换成 leader 身后偏移）。
3. **偶遇打招呼**：两只都空闲且距离 < 120px 时触发——同时停下、互相转向对方、
   各弹一条**成对台词**（新增 `dialogue_pairs.json`：A 说上句、B 接下句），播完各走各的。
   冷却 60 秒，防止粘在一起一直聊。
4. **同步小动作**（锦上添花，最后做）：跟随中 leader 跳，follower 也跳（播同一轨道即可）。

### 技术要点（有三个坑）
- **行为仲裁**：现在每只都有漫游/躲鼠标/惯性三套独立行为，跟随和偶遇是叠加其上的第四五套。
  必须定优先级：`用户拖拽 > 躲鼠标 > 惯性滑行 > 偶遇 > 跟随 > 漫游`——
  没有仲裁的话会出现「一边躲鼠标一边跟人」的鬼畜画面。建议在 DeskPet 里加一个
  `behavior_lock`（当前行为持有者），低优先级行为申请时被高优先级占用就跳过。
- **帧纹理共享**：两只用同一形象时共享 QPixmap 缓存（按 character 名做 key 的模块级 dict），
  否则内存 ×2。
- **谁负责驱动**：跟随/偶遇需要两只互相感知——建议由**一个轻量「互动调度器」**（每 500ms
  tick 一次，读所有实例的位置和状态）统一裁决，而不是两只各自轮询对方——后者会出现
  双方同时向对方打招呼的死锁。

### 验收
- [ ] 绑定两只 → follower 在 leader 漫游时跟上来，保持距离
- [ ] 两只靠近触发打招呼：同时停下、成对台词、冷却生效
- [ ] 拖走其中一只，另一只不受残留状态影响（behavior_lock 正确释放）
- [ ] 同形象两只内存增长 < 30%（纹理共享生效）
- [ ] 全部行为开关可独立关闭，关掉后与单宠行为一致
