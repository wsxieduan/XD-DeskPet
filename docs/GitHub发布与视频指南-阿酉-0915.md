## 问题一：怎么发布？

### 先澄清「做成 agent 插件」

你说的「agent 插件」和「发软件给别人」是两条不同的路：

- **GitHub 发布独立软件**（正道）：观众下载 exe，双击就能用，跟 AI 没关系。
  视频引流的观众是普通用户，这条路才是对的。
- **做成 AI agent 的插件**：比如给 dsh/WorkBuddy 这类 AI 工具写个接口，让 AI 能操控桌宠。
  这是给开发者的玩法，观众用不上，**现阶段不要做**，以后想加再说。

### 发布四步（都由 dsh 或我代劳，你只需要出账号）

1. **注册/登录 GitHub** → 右上角 + → New repository → 起名（比如 `DeskPet`）→ 创建。
2. **上传代码**：把 `D:\dsh\deskpet\` 推上去（git 命令我来或 dsh 来，
   需要你在 GitHub 设置里生成一个「Personal Access Token」给我用；或者你装 GitHub 桌面版点点鼠标也行）。
3. **发 Release（关键一步）**：仓库页面右侧 → Releases → Draft a new release →
   把打包好的 `DeskPet-Lite` 整个文件夹压成 zip 上传 → 发布。
   **观众根本不用懂 git——他们只点 Releases 页面下载 zip**，这是标准姿势。
4. **仓库首页**：README（已有，可让 dsh 补几张截图/GIF）、LICENSE、THIRD-PARTY-NOTICES（已备好）。

## 问题二：署名义务（结论：很轻）

分三层说清楚：

1. **你自己的代码**：我全程审过这个项目的代码——它是 dsh 原创实现的，没有抄任何
   开源项目的源码段。参考「公开的技术知识」（比如 Windows API 怎么调）不构成使用
   别人的代码，**不需要为此署名**。
2. **用到的开源库**（PySide6、numpy、scipy、Pillow 等）：这些有各自的许可证，
   义务很轻——**只要分发时附带它们的声明**。我已经写好 `THIRD-PARTY-NOTICES.md`，
   放进仓库就完成义务了。其中 PySide6 是 LGPL（可以闭源商用免费用的那种，条件就是声明），
   其余全是 BSD/MIT 级别的宽松许可。
3. **你的视频**：视频内容介绍自己的软件，**不涉及任何标注义务**。简介里挂个
   仓库链接 + 一句「使用了开源组件，见声明」就已经是非常规范的做法了。

### 关于「我不商用」

提醒一句：MIT 这类宽松许可证**不限制**别人商用——意思是你不能阻止别人拿去卖。
如果你介意这一点，两个选项：
- **A（推荐）**：只发 exe 不开源——GitHub 上只建仓库放 README 和 Release 的 zip，
  不传源码。没有源码就谈不上别人的商用，你的义务也只剩第三方声明。
- **B**：照常开源（MIT），图个社区口碑和有人帮你修 bug。大多数人选 B，
  「非商用」的执念在开源世界通常没有实际收益。

无论 A/B，`LICENSE` 文件里的版权行记得把「【这里换成你的名字或 GitHub 用户名】」改掉。
