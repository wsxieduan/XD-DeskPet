# BUG 卡：动图上传「生成失败：argument should be a str … not 'list'」（阿酉 · 2026-09-15 13:35）

> 主人实测：上传 奶龙1.gif（110 帧）→ 检测动图正常、选「不抠图」→ 点生成 → 报错。
> **根因已定位，是两个模块的接口约定不一致，几行就能修。**

---

## 根因（已定位到行）

`petctl.py` 745 行组槽位时，把**已拆好的帧列表**塞给了 idle 槽：

```python
slots = {"idle": getattr(self, "_anim_frames", None) or img}
```

而 `petmaker.py` 759 行的 `build_from_slots` 只认两种类型：

```python
if isinstance(src, Image.Image):
    loaded[track] = [src]
else:
    fr, durs = load_sequence(Path(src))   # ← src 是 list，Path(list) 在这里炸
```

`Path(一个list)` 正是主人看到的报错：`argument should be a str or an os.PathLike object
where __fspath__ returns a str, not 'list'`。

也就是说：控制台侧为动图新加的「帧列表」形态，petmaker 侧的 build_from_slots 没有适配——
deskpet 引擎那边认这个形态，控制台生成这边漏了。

## 修法（建议 A，最小改动）

在 `build_from_slots` 的类型分支里补一种「已经是帧列表」的情况：

```python
if isinstance(src, Image.Image):
    loaded[track] = [src]
elif isinstance(src, (list, tuple)):
    loaded[track] = list(src)        # 控制台已经拆好的帧，直接用
else:
    fr, durs = load_sequence(Path(src))
    ...
```

同时把 docstring 里 slots 的类型说明补全（`Path | PIL图 | 帧列表`），
别让下一个调用者再踩。

顺带检查两处联动，动图 110 帧会放大它们的开销：
1. `align_frames` / `frames_to_files` 对 110 帧逐帧处理——确认在这个量级下耗时可接受
   （accept_import 有 UI 冻结问题，见另一张 BUG 卡，修线程化时一起量）；
2. ms 数组在 frames_to_files 裁剪缩放后帧数不变，沿用的前提成立——加一个
   `len(per) == len(frames)` 已有兜底，确认 110 帧场景下 ms 长度真的对齐（GIF 拆帧
   有时会产生 0 时长帧）。
