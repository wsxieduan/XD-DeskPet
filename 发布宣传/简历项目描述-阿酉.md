## 面试讲稿版（60~90 秒）

「这个项目我想回答一个问题：**一个人指挥多个 AI，能不能交付一个真正完整的桌面软件**。
我的做法是把 AI 编成团队：一个开发 Agent 负责写代码，一个质检 Agent 不写任何代码、
只负责审查——每轮输出按 P0/P1 分级的审查报告，写清文件、行号、修法和验收标准，
开发 Agent 修完必须交回执，我再验收。这样跑了 14 轮，从想法到 65MB 的可分发成品
只花了两天。

这个过程中我最重要的产出不是代码，是三样东西：**验收标准的设计**——每个功能开工前
先写清楚『怎么算做完』；**工作流本身**——比如质检方绝不和开发方同时碰文件，
冲突从机制上被消灭；还有一批 AI 时代的测试经验——比如给系统加了自主行为之后，
所有基于固定坐标的旧测试全部失效，这类问题教科书里没有，是我们撞出来的。

桌宠本身反倒是顺带的产品：AI 抠图生成角色、双宠联动，开源在 GitHub 上。」」

## 备好被追问（高频问题与答法）

- **「代码都是 AI 写的，你的技术含量在哪？」**
  → 在需求拆解、验收标准、架构决策和工作流设计。举例：线程化方案是我方提出的
  「代数过期 + 单线程池」；双宠联动我方提前预判了行为仲裁和双调度死锁两个坑，
  写进需求卡后开发 Agent 一次做对——这就是 AI 应用的核心：**把工程判断前置到需求层**。
- **「为什么不自己写？」**
  → 自己写也能写，但指挥两个 Agent 的交付质量更高（每轮都有独立质检）、速度更快
  （48 小时含打包与发布流水线），且全程留档可审计——这是可复制的能力，不是一次性运气。
- **「AI 会写错吗？」**
  → 会，而且犯过只有 AI 会犯的错（漏读报告、上下文丢失导致欠账）。正因如此
  质检 Agent 和人类验收是必需位——这本身就是结论：AI 协作不是替代质检，而是放大它。
