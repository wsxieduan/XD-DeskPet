## 四、主打卖点详解：AI 协作工作流（简历与面试的核心叙事）

### 工作流设计（这是「管理多 Agent」的实证）

- **角色分工**：开发 Agent（编码）+ 质检 Agent（只审查、不写码）+ 人类（需求/决策/验收）；
- **通信协议**：质检方输出分级审查报告（🔴必须修/🟡建议修/🟢观察项，含文件、行号、修法），
  开发方以回执逐条响应；双方通过项目目录中的文件交换，从不同时修改同一文件——
  冲突在机制上被消灭；
- **验收前置**：每个功能开工前先写「需求卡」定义验收标准（含量化指标），
  例：双宠联动需求卡预判了行为仲裁优先级与双调度死锁两个坑，开发 Agent 一次做对；
- **迭代数据**：14+ 轮循环，包括一次「质检视觉验收推翻算法自检指标」的案例
  （自动指标全绿但真图上角色半张脸被清掉——**自动指标不能替代人工验收**的方法论结论）；
- **意外事件处置**：GitHub 反滥用系统误伤新账号（shadow flag），通过官方支持渠道
  用英文工单申诉，全程文档化。

### 由此沉淀的 AI 时代工程经验（面试展开点）

1. **验收标准前置**：AI 时代「怎么算做完」必须在开工前定义，否则 AI 的自信产出无法被证伪；
2. **自动指标会骗人**：夹缝清理的漏白指标 -96% 时，角色半张脸也没了——结构指标
   必须配合视觉/语义验收；
3. **自主行为使旧测试失效**：给系统加「自主漫游」后，所有固定坐标测试的隐含前提
   （被测对象不会自己动）崩塌，测试策略必须分层；
4. **Agent 上下文管理**：开发 Agent 会漏读报告，需要在每轮报告里显式点名未读项；
5. **PySide6 专项**：QRunnable 必须保活引用、Qt 静态方法塞 Python 对象会静默死亡、
   override cursor 是栈——都是无人讲过、靠对照实验实锤的坑。

## 六、面试弹药（高频追问与答法）

**Q：代码都是 AI 写的，你的技术含量在哪？**
→ 需求拆解、验收标准、架构决策、工作流设计。例：线程化方案（代数过期+单线程池）、
双宠联动的仲裁与死锁预判，都是我方在需求层提前给出、开发 Agent 才一次做对的。
**AI 应用的核心能力是把工程判断前置到需求层。**

**Q：AI 会出错吗？**
→ 会，而且犯过经典错误：漏读报告导致欠账、自动指标全绿但视觉验收抓出严重误伤。
所以质检 Agent 与人类验收是必需位——结论：AI 协作不是取消质检，而是放大质检。

**Q：为什么不自己写代码？**
→ 指挥两个 Agent 的交付质量更高（每轮独立质检）、速度更快（48h 含打包发布流水线），
且全程留档可审计——这是可复制的能力。

**Q：项目最难的技术点？**
→ 三层都有：Windows 层（Win11 26200 废掉 WorkerW 后的 z 序方案）、算法层
（白底图上「角色浅色」与「背景」在像素级欠定，最终转向交互引导）、工程层
（PyInstaller 打包的动态 import 链陷阱）。每一层都有档案佐证。
