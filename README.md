# 谢小端桌宠（贴在 Windows 桌面上）

独立小程序：**只在露出壁纸时可见**，被任何窗口盖住就看不见。拖拽换位置，点击有反馈。

| 交互 | 行为 |
|---|---|
| **拖拽** | 按住拖到任意位置，拖动时播放摇摆动画，松手位置记住 |
| **点击** | 播一段反馈动画 + 头上冒出对话框（配色跟随角色）+ 一声轻响 |
| **右键她** | 切换显示层级、大小、关闭 |
| **桌面「桌宠控制台」** | 开关、换形象、换大小、音效、**上传图片生成新桌宠**、**改对话框配色** |

## 二、抠图：现在用 AI 模型了

之前那套纯算法的抠图有根本局限：它只能靠"这个像素离背景色多远"来判断，
**而你的角色本身就带大片浅色**（皮肤、浅发、浅色衣服）。任何阈值都必然二选一 ——
要么把两腿之间那种带阴影的夹缝留成白块，要么把角色的浅色部分弄成半透明。

现在默认走 **AI 分割模型**（rembg + `isnet-anime`，动漫角色专用）：

| | 快速算法 | AI 智能抠图 |
|---|---|---|
| 原理 | 按颜色距离 + 连通性判断 | 神经网络语义分割 |
| 速度 | 2~3 秒 | 3~6 秒（CPU） |
| 复杂背景 | 基本没戏 | 能用 |
| 夹缝/阴影里的背景 | 靠阈值，容易残留 | 模型自己认得出来 |
| 模型 | 不需要 | 首次 176MB（已给你下好） |

控制台上传图片时可以两种任选，**实时预览**（棋盘格底），哪张干净一眼看得出来。

### 残留白边是怎么除掉的

AI 出来的 mask 边缘很软，光靠反预乘还不够 —— 因为边缘像素的颜色本来就等于
`alpha*前景 + (1-alpha)*背景`，当像素本身几乎就是背景色时（obs≈bg），
**数学上解不出真正的前景色**，解出来还是白的。所以最后一步是**直接把这类像素判成背景**：
轮廓外一圈里"发白且低饱和"的像素一律抹成透明。

实测（同一张豆包图）：白边指标 **0.593 → 0.014**，比纯算法（0.000 但夹缝留白）更干净且没有留白。

想自己看效果：**`selftest\cutout-check.png`**（三个视图铺在格纹底上）和 `ai-vs-algorithm.png`（AI 和算法并排对比）。

## 三、对话框配色

点她时头上冒出的那个气泡，颜色有两种模式（控制台里切）：

**① 跟随角色主色（默认）**：从她的立绘里提取主色调，然后按同一个色相生成三色 ——
深色玻璃底、同色相提亮的边框、近白的文字。实测谢小端是暖棕色系，鲸鱼娘是蓝色系。
文字/背景的对比度会自动保证在 WCAG AA 以上（实测 5.20）。

**② 自定义**：控制台里三个取色按钮分别改 背景 / 文字 / 边框，上面有实时预览。

桌宠会把实际用上的颜色写回 `config.json` 的 `bubble_resolved`，所以控制台预览和实际效果一定一致。

## 四、上传图片生成新桌宠

控制台点 **「＋ 上传新桌宠」**：

1. 选图片 → 立刻在棋盘格背景上显示抠图预览
2. 图里有多个角色 → 下拉挑第几个
3. **抠图方式**：智能 AI（推荐）/ 快速算法
4. **抠图强度**（只有快速算法用得上）：柔和 / 标准 / 严格
5. **动态档位**：完全静止 / 静态+点击有反应 / 完整动态（推荐）
6. 起名字 → 生成 → 自动切过去

**动态是完全程序化生成的，不需要你画多张图**：以脚底中心为支点做仿射变换，合成待机、点击、拖拽三段动画。

### 图片要求

| 项 | 要求 |
|---|---|
| 格式 | PNG / JPG / WebP / BMP / GIF / TIFF |
| 体积 | ≤ 24MB，单边 ≤ 4096px |
| 内容 | 一个角色、人物完整不被裁切 |
| 背景 | 用 AI 抠图的话什么背景都行；用快速算法则需要纯色/白底 |

⚠️ **注意 JPEG 不支持透明**。你之前那张「透明底豆包处理谢小端.jpeg」其实是 JPEG，
透明信息在保存时就已经丢了，剩下的只是白底 —— 这种就用 AI 抠图重新处理。

## 六、这次修的四个 bug（都是真踩过的坑）

### 1. 桌宠被无限重启（她老是莫名其妙消失）

**症状**：控制台一开，桌宠每 2.5 秒被重启一次，日志里 20 秒有 9 次启动。

**定位**：给日志加上父进程号，发现每次重启的父进程都是 `pythonw.exe`（控制台）；
再给 `apply()` 加日志，看到它在被反复调用 `apply({"mode": "desktop"})` —— 也就是 `on_layer()`。

**根因**：Qt 的单选按钮默认**按父控件自动互斥**。我把「显示层级」和「对话框配色」两组单选按钮
放在了同一个父控件里，于是它们互相取消选中：刷新界面 → 设 A 组 → 取消 B 组 → 又设 B 组 → 取消 A 组 →
每次都触发一次 `toggled` → `apply()` → 重启桌宠 → 再刷新……死循环。

**修复**：用两个 `QButtonGroup` 显式分组；同时给 `refresh()` 加了统一的 `_syncing` 标志，
同步期间一律忽略控件信号（只堵单个控件迟早会漏）。

### 2. 她看得见但点不到

**症状**：验收测试里"裸露壁纸时看得见她"通过，但点击没反应。

**定位**：`WindowFromPoint` 在她身上返回的是 `SysListView32`（桌面图标层），不是她的窗口 ——
说明点击全被桌面图标层收走了。

**根因**：之前用 `SetWindowPos(hwnd, HWND_BOTTOM)` 把窗口压到 z 序最底，结果落到了桌面图标层**下面**。

**修复**：改成插到 **Progman 正上方**（`SetWindowPos(hwnd, progman, ...)`）——
z 序是「桌面 < 她 < 其他所有窗口」，既露得出来又点得到。

### 3. 诊断脚本自己被 DPI 骗了

上面那条 `WindowFromPoint` 结论，我第一版测出来是"她根本不在那儿"。
原因是诊断脚本（纯 Python，没建 QApplication）**不是 DPI 感知进程**，
Windows 会把传给 `WindowFromPoint` / `SetCursorPos` 的坐标当成逻辑坐标再乘 1.5 ——
测的位置其实是 (237,1344)，早就落到窗口外面了。

**修复**：诊断脚本开头加 `SetProcessDpiAwareness(2)`。这也是为什么用 PySide6 的测试脚本一直是对的（Qt 会设 DPI 感知）。

### 4. 控制台第一版会崩 / 开机闪黑窗口

- `_build_tray()` 排在 `refresh()` 后面，而 `refresh()` 要用托盘菜单的 action → `AttributeError`。已调整顺序。
- **闪黑窗口**：`refresh()` 每秒用 `subprocess` 调 `tasklist`，没加 `CREATE_NO_WINDOW`。
  控制台是 `pythonw`（无控制台），调控制台程序时 Windows 会给子进程新建一个控制台窗口，于是每秒闪一个黑框。
  改成 **ctypes 直接查进程**（`OpenProcess` + `GetExitCodeProcess` + 校验可执行文件名），一个子进程都不开；
  其余调用一律加 `CREATE_NO_WINDOW`。实测修复前后各 8 秒，新建 conhost 数从「+8 以上」变成 **0**。

# 第三轮更新（删除形象 / 自定义台词 / 夹缝清理）

## 一、删除形象

控制台形象那一行现在是「＋ 上传」和「删除」。删除会**直接删掉素材目录**（不可恢复），
删完自动切到剩下的第一个形象。内置形象（paths.DEFAULT_CHARACTER，现在是 nailong）
是兜底形象，禁止删除。

## 二、点击台词可以自己设（文字或图片）

控制台 →「编辑点击台词…」，可以：

- **＋文字**：加任意多条，点她的时候**随机**挑一条
- **＋图片**：选一张图（自动缩到 480px 存进 `assets/bubbles/`），点她时图片直接显示在对话框里
- 编辑 / 删除 / 「恢复内置」

配好的内容存在 `config.json` 的 `bubbles` 字段里：

```json
"bubbles": [
  { "type": "text",  "text": "被摸头了～" },
  { "type": "image", "file": "bubbles/bub-0914193000.png" }
]
```

空数组 = 用内置台词。窗口大小会自动跟着最宽的台词和最大的图片调整。

## 三、夹缝清理（发丝缝 / 脖子边的空隙）

之前 AI 抠完，**被角色轮廓围住的小块背景**（发丝之间的缝、头发和脖子之间的空隙）
还是不透明白块。原因是 AI 常把这些地方判成实心 —— 它既不是"空洞"，也不在轮廓边缘，
所以前两版清理逻辑只能清掉 1.5%。

现在的做法：**不管 AI 怎么说，直接在原图上找"被角色围住的、颜色就是背景的区域"** ——
从画布四边 flood fill 出真正的外背景，剩下的近背景色区域就是内部夹缝，
再按"面积"和"平整度"（色距标准差）筛选。

| | 清理前漏白 | 清理后 | 降幅 |
|---|---|---|---|
| 三视图 | 78605 px | 2688 px | **-96.6%** |
| 豆包图 | 86753 px | 2643 px | **-97.0%** |

上传对话框里有四档：`关闭 / 保守 / 标准（默认）/ 强力`，切换即时重新预览。

**安全性**：清理后最大连通块仍占 99.2%（清理前 100%），内部空洞 5 → 272 个 —— 身体没有被切成碎片。

> ⚠️ **需要你亲自确认一件事**：我没法百分百区分"夹缝"和"角色自己的白色头发/衣服"。
> 请看 **`selftest\gap-before-after.png`**（每对左边是纯 AI、右边是清理后，棋盘格底），
